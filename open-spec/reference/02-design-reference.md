# 02 设计参考

## 目标

把变更分析落成可实施设计，明确架构、模块边界、技术决策、数据策略、风险与回滚。

## 输入清单

- `01-change-analysis.md`
- `00-change-request.md`（如适用）
- 关键 FR/NFR 列表
- 技术栈与运行环境约束

## 设计步骤

1. 方案范围：声明影响模块与非影响模块。
2. 模块分解：定义模块职责、接口、依赖方向。
3. 关键流程：给出主流程与异常流程步骤。
4. ADR 记录：对关键取舍写“方案-备选-决策理由”。
5. 存储设计：涉及持久化时，在主设计文档的“存储与数据设计（如适用）”章节补齐模型、索引、迁移、回滚。
6. 风险闭环：为每个高风险点定义验证动作。
7. 缺口分级：将架构边界、技术取舍、运行环境限制中的未决信息做 `Blocker/Assumption/Nice-to-know` 分类。
8. 用户补齐：若关键 ADR、依赖约束、发布回滚策略存在 `Blocker`，暂停并向用户提问。

## 设计原则

- 低耦合高内聚：避免跨模块隐式依赖。
- 可演进：保留扩展点，避免一次性锁死。
- 可回滚：发布失败可在可接受窗口内恢复。
- 可观测：关键链路可监控、可告警、可排查。

## 存储设计准则

- 字段定义必须包含类型、约束、语义。
- 索引只为查询路径服务，避免过度索引。
- 迁移脚本必须包含前向与回退策略。

## 自检清单

- [ ] 设计章节和 FR 已完成映射
- [ ] 关键决策具备 ADR 记录
- [ ] 风险与回滚可执行
- [ ] 存储方案已并入主设计文档，或明确 N/A 原因
- [ ] 所有设计级 `Blocker` 已整理为待确认问题，未确认前阶段状态为 `NEEDS_USER_INPUT`

## 产出映射

- 主文档：`02-technical-design.md`（包含存储设计章节）
- 阶段交接：`08-task-handoff.md`

## Input Contract（输入契约）

- 任务目标：把变更分析转成可执行技术设计。
- 必读输入：`01-change-analysis.md`、FR/NFR 列表、技术栈边界。
- 上游引用：分析阶段 handoff 摘要与关键风险。
- 输出约束：设计必须给出模块边界、关键决策、风险、回滚与可观测性设计。

## Output Contract（输出契约）

- 必交文档：`02-technical-design.md`。
- 必含内容：模块边界、关键流程、ADR、风险与回滚、存储策略或 N/A，均在同一设计文档中体现。
- 追溯锚点：FR/NFR/ADR/REV ID。
- 交接摘要：写入 `08-task-handoff.md` 的设计结论与下阶段输入。
- 若存在 `Blocker`：门禁状态必须返回 `NEEDS_USER_INPUT`，并附待用户回答的问题包。
