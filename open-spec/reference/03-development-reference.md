# 03 开发参考

## 目标

把设计转成可执行开发任务，并在实施过程中持续维护状态、验证结果、偏差与阻塞。

当设计已可执行且不存在 `Blocker` 时，应直接进入开发，不等待用户再次手动发出开始开发指令。

## 输入清单

- `02-technical-design.md`（存储相关内容位于“存储与数据设计（如适用）”章节）
- 需求追溯关系（FR -> 设计章节）

## 开发步骤

1. 任务拆解：按可独立验证原则拆成 TASK。
2. 追溯绑定：每个 TASK 绑定 FR 与设计章节。
3. 依赖建模：标记前置依赖与并行可行项。
4. 里程碑规划：按迭代定义可验收里程碑。
5. 风险前置：高风险 TASK 优先进入早期迭代。
6. 迭代启动：确认本轮目标 TASK 与完成定义。
7. 执行开发：按依赖顺序推进实现。
8. 执行更新：持续更新 TASK 状态、验证结果与偏差。
9. Task 验收：确认实现与设计一致。

## 开发定向进入规则

当用户显式要求直接进入开发 task 时，按以下准入表执行：

| 输入状态 | 执行动作 |
|----------|----------|
| `03-development.md` 已存在且可执行 | 直接继续开发 |
| `03-development.md` 缺失，且 `02-technical-design.md` 已齐备 | 先生成开发任务，再继续开发 |
| 前置文档缺失 | 仅返回缺失项与阻塞原因，不得伪造开发进展 |

## TASK 状态标准

- 未开始：无代码或实现动作。
- 进行中：已开始但未达成完成定义。
- 已完成：通过本 task 完成定义，具备可验证证据。
- 阻塞：受外部依赖或关键问题阻断。

## 完成定义（DoD）建议

- 与关联 FR 行为一致
- 关键异常路径已处理
- 有对应验证记录
- 文档状态与实现状态同步

## 自检清单

- [ ] 每个 TASK 都有 FR 与设计映射
- [ ] 里程碑具备可验收结果
- [ ] 开发偏差有记录且有纠偏动作
- [ ] 阻塞项有负责人和预计解除时间

## 产出映射

- 主文档：`03-development.md`
- Task 交接：`08-task-handoff.md`

## Input Contract（输入契约）

- 任务目标：形成可执行开发任务并推进实现。
- 必读输入：`02-technical-design.md`（含存储设计内容）、FR 映射。
- 上游引用：设计 task handoff 摘要、风险与回滚约束。
- 输出约束：每个 TASK 都要有状态、完成度、验证结果与偏差说明。

## Output Contract（输出契约）

- 必交文档：`03-development.md`。
- 必含内容：任务分解、依赖、里程碑、开发进展、阻塞、验证记录与纠偏动作。
- 追溯锚点：TASK/FR/REV ID。
- 交接摘要：写入 `08-task-handoff.md` 的完成 TASK、阻塞 TASK 与偏差摘要。
